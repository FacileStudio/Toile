# Toile — Development

How to run the desktop app locally, what the checks are, and how bundles and the landing page
get built.

## Prerequisites

- **Bun** — package manager and script runner for `apps/desktop`. The lockfile is `bun.lock`.
- **A Rust toolchain** — the crate targets edition 2021 and depends on Tauri 2.
- **Tauri's platform prerequisites** — on macOS that is Xcode command line tools. The crate
  also pulls `objc2-web-kit` under `cfg(target_os = "macos")`, so macOS is the only target the
  code has platform-specific handling for.

The frontend pins TypeScript `~5.6.2`, Vite `^6.0.3`, SvelteKit `^2.9.0` and Svelte `^5.0.0`.

## Run

```sh
cd apps/desktop
bun install
bun run tauri dev
```

`tauri dev` runs `bun run dev` for you (`beforeDevCommand`) and waits for
`http://localhost:1420`. The port is fixed on both sides — `strictPort: true` in
`vite.config.js` and a hardcoded `devUrl` in `tauri.conf.json` — so a busy 1420 is a hard
failure, not a fallback. Vite is told to ignore `src-tauri/**` so Rust edits do not trigger a
frontend reload; Cargo handles those.

You can also run the canvas in a plain browser with `bun run dev`, but every `invoke()` call
will reject, so the board loads empty and nothing persists. It is only useful for CSS work.

On first launch the app writes `~/.toile.yml` and creates `~/Toile`. To develop against a
scratch folder, point `folder` somewhere disposable — Toile writes frontmatter into any `.md`
file you move around in the app, and there is no dry-run mode.

## Checks

```sh
bun run check        # svelte-kit sync && svelte-check --tsconfig ./tsconfig.json
bun run check:watch  # the same, watching
cargo clippy --manifest-path src-tauri/Cargo.toml
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
```

`bun run check` is the only check defined in `package.json`. There is **no test suite** on
either side — no `*.test.ts`, no `#[test]`, no `tests/` directory — no `mise.toml`, no
`scripts/check.sh`, no git hooks and no CI workflow. The quality gate is whatever you run
before committing.

Verification is manual. The fastest smoke test is: launch, press `T` and type, drag the note,
then confirm a `<id>.md` appeared in the notes folder with frontmatter matching where you
dropped it. For the sync path, edit that file in another editor and watch the canvas update
without a reload.

## Layout of the desktop app

```
apps/desktop/
  src/
    routes/+page.svelte      The canvas: input, selection, camera, shortcuts, paste and drop
    lib/*.svelte.ts          Rune state classes: board, drawing, links
    lib/*.ts                 Pure helpers: draw, assets, segments, markdown, links, fonts
    lib/components/          Postit, TextBlock, LinkCard, players, minimap, palettes, overlays
    app.css                  Global styles and the liquid-glass surface treatment
  src-tauri/
    src/lib.rs               Commands, markdown codec, watcher, unfurler, YouTube proxy
    src/main.rs              Calls toile_lib::run()
    capabilities/            Tauri permission set for the main window
    icons/                   Bundle icons, generated from icon-source.svg
    tauri.conf.json          Window, CSP, bundle configuration
  build/                     adapter-static output — generated, gitignored
```

`src-tauri/gen/schemas` is generated by Tauri and gitignored; `src-tauri/target` likewise.

## Adding a Tauri command

1. Write the handler in `src-tauri/src/lib.rs` with `#[tauri::command]`. Take
   `state: State<Arc<SyncState>>` if it needs the notes folder, and return
   `Result<T, String>` — the frontend catches the string.
2. Add its name to the `tauri::generate_handler![…]` list in `run()`. Forgetting this is the
   usual cause of "command not found" at runtime.
3. Call it from the frontend with `invoke<T>("name", { args })`. Argument keys are camelCase on
   the TypeScript side and snake_case in Rust; Tauri converts between them.

If the command needs a plugin permission, add it to `src-tauri/capabilities/default.json`. The
current set is `core:default`, `opener:default`, `opener:allow-open-path` and
`clipboard-manager:allow-read-image` — pasting an image from the clipboard depends on that last
one.

## Building the desktop app

```sh
bun run tauri build
```

This runs `bun run build` first, so `../build` holds a fresh SvelteKit static export before
Cargo compiles in release mode. `bundle.targets` is `"all"`, so every format the host platform
supports is produced into `src-tauri/target/release/bundle/`. On macOS that is a `.app` and a
`.dmg`.

The bundle is not signed or notarized by anything in this repo — there is no signing identity
in `tauri.conf.json` and no release workflow. A DMG built here will trip Gatekeeper on another
machine unless it is signed out of band.

## The landing page

`apps/web/` is a single `index.html` with inline CSS and no build step. Edit it and reload the
file in a browser.

```sh
docker build -f apps/web/Dockerfile -t toile-web .
```

The Dockerfile must be built from the **repository root**, not from `apps/web/`, because it
does `COPY apps/web/ /usr/share/nginx/html`. It writes an nginx config that falls back to
`index.html` and serves `/downloads/` with `Content-Disposition: attachment` and a `dmg` MIME
type, then deletes the copied Dockerfile from the web root.

Releasing a new desktop version means committing binaries: `apps/web/downloads/` holds
`Toile-aarch64.dmg` and `Toile-x64.dmg` **in git**, and the page links straight at them. Copy
the DMGs out of `apps/desktop/src-tauri/target/release/bundle/dmg/` under those exact names,
commit, and rebuild the image. The Goga OTF files behind the page's `@font-face` rules are
committed too, in `apps/web/fonts/`.
